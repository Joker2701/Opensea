# spreadbot — парсер вилок опціон × предикт-маркет

Це **сканер з алертами**, не торговий бот: він читає ринки, знаходить
конструкції, що проходять дві умови вилки, і шле картку в Telegram.
**Жодних заявок сам не виставляє і не буде** — рішення й натискання завжди
на вас.

Стратегія: купити **NO** на предикт-маркеті («ETH тестує $4 000 до
30.06.2027» по 62–64¢) і на чистий прибуток цієї ставки взяти довгий
**кол** на біржі опціонів зі страйком нижче порогу. Росте — заробляє кол,
не росте — заробляє ставка. Дві умови, за яких це вилка:

* **(A)** чистий прибуток ставки покриває вартість опціона;
* **(B)** профіт опціона на порозі (де ставка програє) покриває вкладене у ставку.

Бот перебирає всі активні ринки, всі страйки й експірації, рахує обидві
умови в доларах з урахуванням комісій і лотності, і показує тільки те, що
справді проходить.

## Швидкий старт: сканер (без Telegram)

```bash
make test     # 88 тестів: математика, парсинг, сайзинг, наскрізний прогін
make demo     # повний офлайн-прогін на фікстурах (без мережі)

cp config/config.example.yaml config/config.yaml
python3 -m spreadbot -c config/config.yaml scan --save   # живе сканування, разово
python3 -m spreadbot chain --asset ETH                    # поверхня волатильності
python3 -m spreadbot markets                               # розпізнані ринки
```

## Telegram: алерти й керування з телефону

```bash
export SPREADBOT_TG_TOKEN="<токен від @BotFather>"
python3 -m spreadbot -c config/config.yaml bot
```

Напишіть боту `/start` — ви станете власником, `/menu` відкриє панель з
кнопками: капітал на угоду, поріг едж, які активи/біржі сканувати, пауза.
Усе крутиться прямо з телефону, без перезапуску процесу.
Детально — [`docs/TELEGRAM_SETUP.md`](docs/TELEGRAM_SETUP.md).

Залежності: `requests` і `PyYAML`. Уся математика — на стандартній бібліотеці.

## Що видає

```
[ 0.26] NO+call@2800   (polymarket × deribit)
  ринок : Will Ethereum hit $4,000 by June 30, 2027?
  ціна YES ринку : 37.00%   модель: 27.48%   едж: +9.5 в.п.

  НОГА 1   NO × 4,800 @ 0.627  -> вартість   3,008.00
  НОГА 2   BUY 4 × ETH-25JUN27-2800-C @ 435.98  ->   1,746.79

  УМОВА A  прибуток ставки ≥ премія опціона      : ✓ запас      45.21
  УМОВА B  профіт опціона на порозі ≥ ставка     : ✓ запас      45.21
  найгірший P&L  :      12.25  (+0.26%)
  очікуваний P&L :     430.66  (+9.06%, ~+10.7% річних)
  P(прибуток)    : 100.0%   P(збиток):   0.0%
```

Найгірший сценарій тримається біля нуля (комісія + невеликий сліпедж на
вихід) — саме так і має виглядати конструкція, де обидві умови вилки
виконані. Плюс сценарна таблиця, теплова карта дострокового виходу
(ціна × час) і стрес-тест волатильності — доступні по команді, у сам
алерт не заводяться, щоб не захаращувати.

## Структура

```
spreadbot/
  models.py               канонічні типи (EventClaim, OrderBook, Structure, Metrics)
  adapters/                Polymarket, Kalshi, Deribit, Bybit + офлайн-режим
  parsing/claim.py         заголовок ринку -> нормалізоване твердження
  pricing/                 Black-76, поверхня IV, цифрові та бар'єрні ймовірності
  strategy/fork.py         дві умови вилки
  strategy/sizing.py       підбір розмірів ніг під умови і ризик-ліміти
  strategy/payoff.py       сценарії, P&L, переоцінка в будь-який момент
  scanner/                 оркестрація і ранжування
  report.py                картки, таблиці, теплові карти
  notify/telegram_bot.py   Telegram-бот: алерти + панель керування
  storage/                 SQLite: знімки, знахідки, налаштування бота
```

## Стан

Ядро (математика, сценарії, сайзинг, дві умови вилки, звіти) і Telegram-бот
працюють і покриті тестами на офлайн-фікстурах. Адаптери живих API написані
за документацією, але в середовищі збірки мережа до бірж закрита — перша
перевірка на живих даних: `python3 -m spreadbot chain --asset ETH`.
Дефолти: біржа опціонів **Bybit**, капітал на угоду **$10 000** (діапазон
$5–25 тис. — правиться з `/menu`).
