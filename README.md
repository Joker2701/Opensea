# spreadbot — пошук вилок між крипто-опціонами і предикт-маркетами

Бот автоматично шукає конструкції «ставка на предикт-маркеті + опціон на
біржі», у яких виконуються дві умови вилки:

* **(A)** чистий прибуток ставки покриває вартість опціона;
* **(B)** збиток по ставці покривається профітом опціона на порозі спрацювання.

Приклад стратегії: купити **NO** на «ETH тестує $4 000 до 30.06.2027» по 62–64¢
і на чистий прибуток цієї ставки взяти довгий **кол** на ETH зі страйком
нижче порогу. Росте — заробляє кол, не росте — заробляє ставка.
Бот перебирає всі активні ринки, всі страйки й експірації і залишає тільки
ті пари, де вилка справді існує з урахуванням комісій, лотності та стакана.

## Швидкий старт

```bash
make test     # 46 тестів: математика, парсинг, сайзинг, наскрізний прогін
make demo     # повний офлайн-прогін на фікстурах (без мережі)

cp config/config.example.yaml config/config.yaml
python3 -m spreadbot -c config/config.yaml scan --save   # живе сканування
python3 -m spreadbot chain --asset ETH                   # поверхня волатильності
python3 -m spreadbot markets                             # розпізнані ринки
```

Залежності: `requests` і `PyYAML` (тільки для мережі й конфігу).
Уся математика — на стандартній бібліотеці.

## Що видає

```
[ 0.20] NO+call@2800   (polymarket × deribit)
  ринок : Will Ethereum hit $4,000 by June 30, 2027?
  ціна YES ринку : 37.00%   модель: 27.48%   едж: +9.5 в.п.

  НОГА 1   NO × 9,600 @ 0.631  -> вартість   6,056.00
  НОГА 2   BUY 8 × ETH-25JUN27-2800-C @ 435.98  ->   3,493.58

  УМОВА A  прибуток ставки ≥ премія опціона      : ✓ запас      50.42
  УМОВА B  профіт опціона на порозі ≥ ставка     : ✓ запас      50.42
  найгірший P&L  :    -304.42  (-3.19%)
  очікуваний P&L :     734.36  (+7.69%, ~+9.1% річних)
  P(прибуток)    :  96.2%
```

Плюс сценарна таблиця, теплова карта дострокового виходу (ціна × час)
і стрес-тест волатильності.

## Структура

```
spreadbot/
  models.py            канонічні типи (EventClaim, OrderBook, Structure, Metrics)
  adapters/            Polymarket, Kalshi, Deribit, Bybit + офлайн-режим
  parsing/claim.py     заголовок ринку -> нормалізоване твердження
  pricing/             Black-76, поверхня IV, цифрові та бар'єрні ймовірності
  strategy/fork.py     дві умови вилки
  strategy/sizing.py   підбір розмірів ніг під умови і ризик-ліміти
  strategy/payoff.py   сценарії, P&L, переоцінка в будь-який момент
  scanner/             оркестрація і ранжування
  report.py            картки, таблиці, теплові карти
  storage/db.py        SQLite: знімки, знахідки, позиції
```

## Стан

**M0 — каркас.** Математика, сценарний рушій, сайзинг, звіти і офлайн-демо
працюють і покриті тестами. Адаптери живих API написані за документацією,
але в середовищі збірки мережа до бірж закрита — перша перевірка на живих
даних це `python3 -m spreadbot chain --asset ETH`.
Далі за дорожньою картою: живі дані → моніторинг позицій → paper trading →
виконання. Деталі — в [`docs/PLAN.md`](docs/PLAN.md#9-дорожня-карта).
