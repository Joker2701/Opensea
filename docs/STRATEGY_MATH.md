# Математика стратегії

Позначення: `S` — спот, `F` — форвард на термін `T`, `K` — страйк, `B` — бар'єр,
`σ` — волатильність, `N(·)` — функція розподілу нормального закону,
`ν = μ − σ²/2` — знос логарифма ціни, `m = ln(B/S)`.

Уся реалізація — у `spreadbot/pricing/`, кожна формула нижче має тест
у `tests/test_pricing.py`.

---

## 1. Опціон: Black-76 від форварда

Крипто-опціони котируються від форварда, а не від споту:

```
d₁ = [ln(F/K) + σ²T/2] / (σ√T),    d₂ = d₁ − σ√T
Call = DF · [F·N(d₁) − K·N(d₂)]
```

Для Deribit премія котирується **в ETH**, тому USD-премія = `price × underlying_price`,
де `underlying_price` — форвард відповідної експірації (не спот!).

## 2. Цифровий опціон: ймовірність «S_T > K»

Ціна контракту, що платить $1, якщо `S_T > K`, це мінус похідна колла за страйком:

```
Digital(K) = −∂C/∂K = DF·N(d₂) − Vega · dσ/dK
```

Другий член — поправка на скью. Без нього ймовірність систематично зміщена:
в крипті `dσ/dK < 0`, тож «голий» `N(d₂)` занижує ціну цифрового колла.

Модельно-незалежна альтернатива — з реальних котирувань двох страйків:

```
Digital ≈ [C(K₁) − C(K₂)] / (K₂ − K₁)
```

Це не «теоретична» ціна, а **торгована**: рівно цей call-spread можна купити.
Обмеження: точність упирається в крок страйків. Біля $3000 крок на Deribit —
$200–400, тому «цифрова реплікація» має зону невизначеності шириною в цей крок,
і саме в ній концентрується збиток конструкції.

## 3. Бар'єр: ймовірність торкнутись

Ключова формула всієї стратегії — принцип відображення:

```
P(max_{t≤T} S_t ≥ B) = N[(−m + νT)/(σ√T)] + exp(2νm/σ²) · N[(−m − νT)/(σ√T)]
```

Для `B < S` (бар'єр знизу) формула дзеркальна. Практичне правило: ймовірність
**торкнутись** приблизно вдвічі більша за ймовірність **закритись вище** того
самого рівня. Той, хто порівнює touch-ринок із `N(d₂)`, побачить «едж» удвічі
більший за справжній.

`σ` береться **на рівні бар'єра**, а не ATM: у крипті різниця сягає 5–15 вол-пунктів.

## 4. Спільна подія: «торкнулось І закрилось нижче»

Це і є «зона болю» стратегії:

```
P(max ≥ B, S_T ≤ K) = exp(2νm/σ²) · N[(x − 2m − νT)/(σ√T)],   x = ln(K/S)
```

Перевірка коректності (тест `test_touch_decomposition`):

```
P(touch) = P(touch ∧ S_T ≤ B) + P(S_T > B)
```

Приклад (S=2400, B=4000, T=0,85, σ=0,60):

| Подія | Ймовірність |
|---|---|
| торкнулось 4000 | 27,0% |
| торкнулось і закрилось ≤ 3400 | 10,4% |
| торкнулось і закрилось ≤ 2600 | 4,6% |

## 5. Час першого торкання

Ставка на touch програє **в момент торкання**, а опціон у цей момент ще живий.
Щоб оцінити його вартість, потрібен розподіл моменту `τ` (обернено-гаусів):

```
f(τ) = |m| / (σ√(2πτ³)) · exp[ −(m − ντ)² / (2σ²τ) ]
```

Інтеграл по `[0, T]` дорівнює `P(touch)` — це теж перевірено тестом.
Практичний висновок: **раннє торкання нестрашне** (у колла лишається багато
часової вартості), **пізнє — небезпечне**. Тому хеджувальний страйк має бути
**нижче бар'єра**: тоді на бар'єрі опціон має внутрішню вартість `B − K`,
яка не залежить від того, скільки часу лишилось.

## 6. Умови існування вилки

На $1000 виплати ставки NO, куплену за `p` (тобто вкладено `1000p`),
з `r` одиниць базового активу в коллі зі страйком `K` за премію `c`:

**(A) Прибуток ставки покриває премію** (сценарій «ставка виграла»):

```
1000·(1 − p) ≥ r·c        →        r ≤ 1000·(1 − p)/c
```

**(B) Виплата опціона на бар'єрі покриває ставку** (сценарій «торкнулось»):

```
r·(B − K) ≥ 1000·p        →        r ≥ 1000·p/(B − K)
```

Вилка існує, якщо вікно непорожнє:

```
1000·p/(B − K)  ≤  r  ≤  1000·(1 − p)/c
```

Числа з демо (p = 0,63, B = 4000, K = 2600, c ≈ 508):

```
0,45 ≤ r ≤ 0,79
```

Вікно непорожнє → вилка є. Оптимум — біля верхньої межі: там максимальний
хедж при збереженні умови (A). Саме це вікно шукає `strategy/sizing.py`,
але не аналітично, а перебором по всьому сценарному розподілу — бо реальні
комісії, лотність і скью роблять аналітичні межі лише орієнтиром.

**Чому саме на порозі.** Ставка програє тоді і тільки тоді, коли ціна дійшла
до `B`. У цей момент опціон має внутрішню вартість `B − K` плюс часову —
це і є його мінімальний профіт в області «ставка програла»: вище порогу
опціон коштує лише більше. Тому перевірка на порозі (без урахування часової
вартості) — консервативна оцінка знизу.

Практичний наслідок для вибору страйка: **страйк має бути нижче порогу**.
Тоді на порозі опціон має внутрішню вартість, яка не залежить від того,
скільки часу лишилось до експірації.

## 7. Вартість заморожених грошей

Ставка платить $1 у день резолву, а гроші вкладені сьогодні. Справедлива ціна:

```
Fair(YES) = P(подія) · e^{−rT}
```

При `r = 4%` і `T = 0,85` дисконт ≈ 3,3 п.п. Для едж у 9,5 п.п. це третина.
У боті — параметр `rate_usd`.

## 8. Поверхня волатильності

* по страйку — лінійно в `k = ln(K/F)`, плоска екстраполяція за межами лістингу;
* по терміну — лінійно в **загальній дисперсії** `w = σ²T` (інтерполяція самої
  `σ` створює календарний арбітраж);
* `dσ/dK` — чисельна похідна, потрібна для цифрових.

Обмеження: якщо подія довша за найдальшу лістовану експірацію, `σ` — це
екстраполяція, і бот ставить прапорець `extrapolated_iv`.

## 9. Межі точності моделі

Модель потрібна для двох речей: оцінити ймовірність події (щоб рахувати едж)
і оцінити вартість опціона в проміжні моменти. Ось де вона наближена
(робота для M3+):

* **сталу σ у бар'єрних формулах** — реальність має вол-оф-вол і стрибки;
  стрибок «перескакує» бар'єр інакше, ніж дифузія;
* **різницю джерел резолву** (1-хвилинний хай Binance vs індекс Deribit);
* **зміну поверхні в часі** — mark-to-market рахується за припущенням
  sticky-strike, а стрес-тест ±10 в.п. показує чутливість до цього припущення;
* **кореляцію ліквідності з рухом** — на бар'єрі спреди розширюються саме тоді,
  коли треба виходити (частково закладено параметром `unwind_cost_frac`).
